# Agent网关与策略中心软件需求分析说明

整理日期：2026-10-16。证据基线：`f052aa7`。能力对应：软件需求能力。

本文根据项目已有方案、需求清单、接口契约和代码补充整理，不追认历史评审结论。本人承担两个正式服务的需求分析、设计开发和跨模块联调；外部IDaaS、IAM、Agent管理面、真实MCP网关由对应团队提供。

## 1. 背景与目标

业务Agent需要代表用户调用MCP工具。工具调用同时受到用户实际授权范围、Agent订阅能力及应用所有者策略的约束，需要一条可解释、可联调的登录授权链路，以及独立维护权限点和策略的服务。

本模块目标是：业务Agent通过网关接入登录和资源令牌申请；策略中心提供权限点、工具映射、Agent订阅和策略数据；MCP运行时依据TR和策略控制实际工具调用。Demo承接开发者自测，不承担真实MCP生产网关职责。

## 2. 角色与职责

| 角色或模块 | 诉求与职责 |
| --- | --- |
| 业务用户 | 登录业务Agent，对工具所需权限点作出授权选择 |
| 业务Agent开发者 | 接入登录、授权和票据交换，维护自己的`site_session`及TR缓存 |
| Agent管理面 | 提供Agent标识、应用归属、允许回跳域名和订阅权限点 |
| Agent网关 | 校验接入信息、编排IDaaS/IAM、管理短事务及一次性票据 |
| MCP网关及工具提供方 | 上报工具与权限点映射，运行时校验令牌并执行策略裁决 |
| 策略中心 | 存储权限点、工具映射、Agent订阅及策略，提供管理和查询接口 |
| IDaaS/IAM | 分别提供用户登录授权及令牌签发能力 |

## 3. 主要使用场景

1. 用户首次访问业务Agent：浏览器跳转统一登录，业务后端用`ticketST`换回用户信息并建立本地会话。
2. 用户请求受保护工具：业务Agent上报`required_tools`，网关解析权限点并检查Agent订阅，发起用户授权。
3. 用户授权完成：网关完成`code -> Tc`及IAM令牌链路，业务后端用`token_result_ticket`换TR并缓存。
4. 业务Agent调用工具：MCP网关检查TR授予范围及当前Agent用户策略，决定是否执行目标工具。
5. 管理员维护权限数据：上报权限点、覆盖订阅集合、维护策略、停用恢复数据，必要时硬删除并清理引用。

## 4. 功能需求与验收条件

表内测试类和方法在[测试报告](./04_开发者测试与自动化验证报告.md)中列出。这里的“验证”指已有本地自动化范围。

| 编号 | 需求 | 实现入口 | 验收条件与现有证据 |
| --- | --- | --- | --- |
| RQ-01 | 统一登录并交付用户信息 | `GatewayAuthService`、`GatewayAuthController` | base回调仅返回票据和业务state，后端交换得到用户信息；`AgentGatewayFlowTest`主流程通过 |
| RQ-02 | 授权后通过后端交付TR | `GatewayAuthService`、`ResourceTokenController` | 返回授权跳转，完成回调后交换TR；顺序重复交换被拒绝；同上测试 |
| RQ-03 | 校验Agent订阅范围 | `ResourceTokenService` | 将工具解析为所需权限点，未全部订阅时返回403；`shouldRejectResourceTokenWhenPermissionPointIsNotSubscribed` |
| RQ-04 | 使用用户实际同意的范围 | `RealIdaasTokenClient` | 从Tc的`consented_scopes`读字符串数组，缺少有效范围时业务授权失败，不用事务申请范围兜底；IDaaS客户端测试 |
| RQ-05 | 适配IAM三段令牌接口 | 三个`RealIam*TokenClient` | 获取网关自身token，再获取业务Agent T1，最后T1与Tc换TR；HTTP路径、请求头、请求体和缓存复用断言通过 |
| RQ-06 | 查询工具与权限点双向映射 | `PolicyResolutionService` | 两个resolve接口不带`agentId`，只解析生效数据；有映射返回对应集合，无对应结果返回空数组 |
| RQ-07 | 维护权限点归属及查询 | `PolicyCatalogController`、`PolicyResolutionService` | 权限点含`enterprise/appId`，查询以企业为必填条件，可增加应用、code、状态过滤；数据库集成测试 |
| RQ-08 | 维护Agent用户级策略 | `PolicyResolutionService` | 单条策略绑定一个权限点，条件支持`subject.user_id`的`equals/in`，effect支持`PERMIT/DENY`；查询仅返回生效策略 |
| RQ-09 | 覆盖Agent订阅快照 | `upsertAgentPermissionPoints` | 接口接收数组，去空去重排序，存为逗号分隔字符串；再次提交覆盖，空数组清空；对应测试通过 |
| RQ-10 | 支持停用、恢复及物理删除 | `PolicyResolutionService` | `ACTIVE/INACTIVE`控制运行时可见性；硬删除清理映射、策略、条件值及订阅引用，保留工具主表；对应测试通过 |
| RQ-11 | 支持mock和real分层联调 | 外部client端口及profile、Demo的`McpGatewayClient` | 本地可模拟登录授权，real客户端可独立验证协议；Demo MCP模式独立切换；配置选择与契约测试通过 |
| RQ-12 | 工具运行时同时受TR和策略约束 | Demo的`MockMcpGatewayClient` | TR未授予、Agent不匹配、命中DENY、PERMIT未命中、工具反查不覆盖均拒绝；六个Mock MCP测试验证 |

RQ-12在本仓库的交付是运行时规则的Mock验证，不表示已交付真实MCP网关的验签、部署或生产访问控制。

## 5. 核心接口契约

| 接口组 | 主要接口 | 业务约定 |
| --- | --- | --- |
| 登录 | `GET /gw/auth/login`、`GET /gw/auth/base/callback`、`POST /gw/auth/ticket/exchange` | 用户信息经业务后端交换，业务Agent自行维护登录态 |
| 授权 | `POST /gw/token/resource-token`、`GET /gw/auth/authorize`、`GET /gw/auth/consent/callback`、`POST /gw/token/result/exchange` | 申请阶段返回跳转地址；浏览器回跳只交付票据和关联参数 |
| 权限点 | `/internal/v1/permission-points/`下的`batch-upsert`、`query`、`resolve-by-tools`、`resolve-by-codes`、`batch-hard-delete` | 管理归属和全局工具映射，查询无结果为空集合 |
| 订阅和策略 | `/internal/v1/agent-permission-points/batch-upsert`及`/internal/v1/agent-strategies/`下的写入、查询、硬删除 | 订阅是全量快照；策略仍带Agent维度 |

完整字段、请求响应示例以[Agent网关接口](../final_design/04_接口设计明细/02_Agent网关接口.md)、[策略中心接口](../final_design/04_接口设计明细/03_策略中心接口.md)及实际基线代码为依据。

## 6. 安全与非功能要求

| 编号 | 要求 | 当前验证或约束 |
| --- | --- | --- |
| NF-01 | 浏览器回跳URL不携带Tc、TR和用户信息 | 设计及代码检查；主流程测试验证票据交付及部分敏感字段缺失，未做全量浏览器泄露扫描 |
| NF-02 | 一次性票据短期有效，绑定Agent及相关请求 | 当前Caffeine设置5分钟TTL，TR结果绑定`request_id`；已测顺序重复消费，并发原子消费和过期边界待专项验证 |
| NF-03 | TR是用户授权上限，策略不能扩权 | Demo运行时先检查所需权限点是否在TR内，再执行策略及工具覆盖检查 |
| NF-04 | 权限点查询与危险删除有归属条件 | 权限点查询和硬删除使用`enterprise`，策略硬删除使用`agentId`；这不替代调用方认证及企业授权 |
| NF-05 | 多表写入和级联删除保持一致 | 服务方法使用事务；正常写入、级联清理已测，故障注入回滚及并发冲突待补 |
| NF-06 | 可维护、可测试、便于跨团队接入 | 提供分层代码、HTTP契约模拟、测试数据、手工SQL和接入文档；覆盖率和性能指标需由项目门槛确定 |
