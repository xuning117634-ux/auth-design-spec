以下五段可用于任职系统的“举证”栏，附件与待补项应同时提交。是否勾选“自检符合”，仍应按第3节核对。

### 2.1 软件需求能力

本人主导 Agent 网关和策略中心的软件需求分析，围绕业务 Agent 统一登录、用户委托授权、资源令牌获取及 MCP 工具权限控制，梳理业务 Agent、Agent 网关、策略中心、IDaaS、IAM 与 MCP 网关的职责和接口依赖。将需求落实为一次性登录票据、授权结果票据、工具与权限点双向映射、Agent订阅快照、用户级策略管理及数据删除等可验收条目，明确权限点归属、用户实际授权范围和异常处理规则，并维护正式设计、接口请求响应示例和业务接入指南。本次补充形成《软件需求分析说明》，建立需求、实现与测试的对应关系。举证见附件01及其引用的需求清单、设计和接口文档；历史需求确认及本人责任证明待补充。

### 2.2 软件设计能力

本人负责 Agent 网关和策略中心的模块设计与可行性验证，识别浏览器回跳携带敏感凭据、申请范围与实际授权范围混淆、工具权限映射与Agent策略职责混淆等关键设计问题。采用后端交换一次性票据、以IDaaS实际同意的权限点为授权来源、分离全局工具映射和Agent维度策略的方案，并通过Mock登录授权流程、外部HTTP契约测试及H2数据库集成测试验证核心行为。本次形成《系统设计验证报告》，记录方案依据、验证结果和并发消费、多实例、真实MySQL等尚需补充的验证边界。举证见附件02、04及对应代码和测试；正式设计评审记录待补充。

### 2.3 软件实现能力

本人承担 Agent 网关、策略中心的主要实现及维护工作，完成登录与授权编排、IDaaS/IAM适配、Agent管理面查询、权限点与工具映射、订阅快照、策略管理及事务性级联删除，并配套Demo完成开发者自测。开发过程中结合AI辅助拆解需求、生成实现和测试草稿、分析接口差异及检视变更，由本人核对接口协议、模块边界和测试结果。当前两个正式服务的Java源文件共4,808物理行，个人有效代码量需按公司口径另行认定，未据此直接声称满足个人4K要求。代表性功能与修复提交均可追溯，代码与测试同步维护。举证见附件03、04、05；个人4K代码统计、检视记录、静态检查、缺陷率和交付质量证明待补充。

### 2.4 软件验证能力

本人为负责模块设计并维护自动化开发者测试，通过Spring Boot与MockMvc验证登录授权和策略中心接口，使用MockRestServiceServer复用外部HTTP模拟能力，并以H2的MySQL兼容模式运行策略中心数据库集成测试。用例覆盖一次性票据顺序重复使用、订阅边界、IDaaS/IAM请求契约、权限点停用恢复、订阅覆盖、级联删除、TR字段解析及策略拒绝等场景。2026-10-16在当前基线执行根工程`mvn -q test`，三个应用共53个测试全部通过，其中两个正式服务38个、Demo 15个，失败、错误和跳过均为0。举证见附件04；公司要求的覆盖率报告、门槛及CI实际运行记录待补充。

### 2.5 软件维护能力

本人参与跨模块联调问题定位与修复，针对IDaaS回调成功但后端交换用户信息失败的问题，沿回调、一次性票据和token请求逐层定位客户端认证方式差异，改用`client_secret_basic`并同步回归断言；针对IAM业务AI账号拼接错误，将账号来源修正为`Agent_ + agentId`；针对真实TR结构变化，统一从`aud`、`agency_user.user`中的`uid`和`agency_user.consented_scopes`提取鉴权上下文，配套修改令牌生成、解析、Demo调用及测试。三个案例均有代码和提交依据，举证见附件05。目前按开发联调维护经历举证，不能代替“处理生产网上问题”的证明，相关工单和上线验证记录待补充。
