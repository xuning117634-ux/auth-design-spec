# Agent人机委托机制交付计划

| 项目 | 内容 |
| --- | --- |
| 目标1 | 2026-06-12 走通基础授权委托最小流程 |
| 目标2 | 2026-06-20 走通包含A2A的完整流程 |
| 涉及服务 | Agent Gateway、策略中心、MCP Gateway |
| 验收方式 | 以端到端联调链路为准，服务自测作为前置条件 |
| 总体验收人 | 吕剑、李彬 |
| 试点目标 | 保障财经试点正常上线 |

---

## 1. 当前基础与建设重点

| 服务 | 当前基础 | 本期建设重点 |
| --- | --- | --- |
| Agent Gateway | 已具备A2A协议通道能力，已具备基础Agent注册能力 | 补齐授权委托链路中的Token/Session/Cookie能力、入口代理、与策略中心/MCP Gateway的联调接口 |
| MCP Gateway | 已有MCP工具调用基础能力 | 补齐工具标签定义方案、工具风险等级、数据范围元数据、Token校验与Cookie换取链路 |
| 策略中心 | 需要从头开始建设 | 建设委托策略、工具标签、权限验证、委托链解析、实时确认规则和策略缓存 |

---

## 2. 总体交付目标

本计划分两个阶段交付：

1. **基础授权委托最小流程**：用户通过Agent发起工具调用，系统完成Token生成、委托策略校验、MCP工具鉴权、Cookie受控换取和传统API调用。
2. **完整流程**：在基础流程上补齐实时确认、A2A委托链传递、A2A工具调用鉴权和完整审计闭环。

---

## 3. 2026-06-12：基础授权委托最小流程

### 3.1 目标链路

```text
Copilot/业务入口
  -> Agent Gateway
  -> Agent
  -> MCP Gateway
  -> 策略中心
  -> Agent Gateway换取Cookie
  -> 传统业务API
```

### 3.2 Agent Gateway交付清单

| 功能 | 交付范围 |
| --- | --- |
| Agent注册与查询 | 基于已有基础Agent注册能力，补齐联调所需字段和查询接口 |
| 入口代理路由 | 支持Copilot/业务入口通过网关调用目标Agent |
| Session管理 | 支持基于用户Cookie创建和维护Session |
| 任务级Token | 支持生成、缓存、验证任务级Token |
| Cookie换取 | 支持MCP Gateway根据Token受控换取Cookie |
| 基础审计 | 记录Token生成、验证、Cookie换取、入口调用日志 |

### 3.3 策略中心交付清单

| 功能 | 交付范围 |
| --- | --- |
| 服务骨架 | 从头建设策略中心服务骨架、基础存储、基础缓存和接口规范 |
| 委托策略管理 | 支持创建、查询、更新、删除基础委托策略 |
| 工具标签管理 | 支持保存和查询工具标签、风险等级、工具元数据 |
| 权限验证 | 支持按userId、agentId、toolName、dataRange校验是否允许调用 |
| 数据范围校验 | 支持租户、应用、数据源等基础范围判断 |
| 策略缓存 | 支持基础缓存和策略变更后的刷新 |
| 基础审计 | 记录策略创建、变更、权限验证日志 |

### 3.4 MCP Gateway交付清单

| 功能 | 交付范围 |
| --- | --- |
| MCP工具列表 | 支持Agent获取工具列表 |
| MCP工具调用 | 支持Agent携带Token调用工具 |
| 工具标签定义方案 | 补齐工具分类、风险等级、权限标签、数据范围标签的定义和样例 |
| Token校验 | 调用Agent Gateway验证Token |
| 工具鉴权 | 调用策略中心完成权限验证 |
| 数据注入 | 根据Token和策略结果注入appName、tenantId、dataRange |
| 令牌转换/换取链路 | 补齐从Agent携带Token到MCP可调用传统API所需的验证、换取和上下文转换能力 |
| Cookie还原调用 | 调Agent Gateway换取Cookie并调用传统API |
| 工具审计 | 记录工具调用、鉴权结果、API调用结果 |

### 3.5 阶段验收标准

| 验收项 | 标准 |
| --- | --- |
| 主链路打通 | 从业务入口到传统API返回结果，全链路可跑通 |
| Cookie安全 | Cookie不进入Agent，只在Agent Gateway和MCP Gateway受控链路中使用 |
| Token有效 | Agent工具调用必须携带任务级Token，无效Token被拒绝 |
| 权限生效 | 未授权工具调用被拒绝，已授权工具调用可执行 |
| 数据范围生效 | 工具调用参数以Token和策略中心结果为准 |
| 审计可查 | Token、策略验证、工具调用、Cookie换取均有日志 |

## 4. 2026-06-20：完整流程，包含A2A

### 4.1 目标链路

```text
用户请求
  -> Agent Gateway
  -> Agent A
  -> Agent Gateway A2A代理
  -> Agent B
  -> MCP Gateway
  -> 策略中心解析委托链
  -> 传统业务API
```

### 4.2 Agent Gateway交付清单

| 功能 | 交付范围 |
| --- | --- |
| A2A代理路由 | 基于已有A2A协议通道能力，接入授权委托和Token上下文 |
| calleeToken生成 | 为被调Agent生成包含完整委托链的任务级Token |
| 委托链传递 | 支持user -> Agent A -> Agent B链路上下文传递 |
| 实时确认通道 | 支持接收MCP Gateway确认请求并转发到前端 |
| 确认结果回传 | 支持将用户确认结果返回MCP Gateway |
| A2A审计 | 记录A2A调用链路、Token、确认、异常日志 |

### 4.3 策略中心交付清单

| 功能 | 交付范围 |
| --- | --- |
| A2A委托策略 | 支持配置Agent到Agent的委托关系和目标Agent范围 |
| 委托链解析 | 支持解析多级委托链并计算有效权限 |
| 权限交集计算 | 支持A2A场景下工具权限、数据范围取交集 |
| 实时确认规则 | 支持高危工具确认规则配置和查询 |
| 临时授权 | 支持确认通过后的单次或短期临时授权 |
| 完整审计 | 记录委托链解析、确认规则命中、临时授权日志 |

### 4.4 MCP Gateway交付清单

| 功能 | 交付范围 |
| --- | --- |
| A2A Token识别 | 支持识别包含委托链的calleeToken |
| 委托链鉴权 | 调策略中心验证A2A委托链和权限交集 |
| 高危工具确认 | 对needConfirm结果暂停执行并发起确认 |
| 确认后重试 | 用户确认通过后继续执行工具调用 |
| 权限拒绝处理 | 用户拒绝或确认超时后拒绝工具调用 |
| 完整审计 | 记录A2A工具调用、确认等待、确认结果和API调用 |

### 4.5 阶段验收标准

| 验收项 | 标准 |
| --- | --- |
| A2A链路打通 | Agent A可通过Agent Gateway调用Agent B |
| 委托链正确 | Token中包含完整委托链，策略中心可解析 |
| 权限不放大 | A2A场景下权限和数据范围按交集生效 |
| 高危确认闭环 | 高危工具必须确认后执行，拒绝或超时不执行 |
| 异常可处理 | A2A无权限、目标Agent不可用、Token失效均有明确错误 |
| 审计完整 | 可追溯用户、Agent A、Agent B、工具、策略、确认和API调用 |

## 6. 冲刺推进机制

正式开发冲刺期间，每周至少同步两次进展，围绕“架构开发进展”和“业务对接进展”两条线推进，确保财经试点上线目标不受阻塞。

| 机制 | 频率 | 参与方 | 输出 |
| --- | --- | --- | --- |
| 架构开发进展同步 | 每周至少1次 | Agent Gateway、策略中心、MCP Gateway负责人，架构相关人员 | 模块开发进度、接口联调状态、技术风险和阻塞项 |
| 业务对接进展同步 | 每周至少1次 | 业务入口/BFF、业务Agent、财经试点对接方、三网关/中心负责人 | 业务接入进度、试点场景验证状态、上线风险和待决策事项 |
| 关键问题闭环 | 按需，阻塞问题当天拉通 | 问题相关负责人 | 明确责任人、解决方案和完成时间 |
| 阶段验收检查 | 6.12、6.20前各一次 | 吕剑、李彬、各模块负责人 | 阶段验收结论、遗留问题、上线风险判断 |

---

## 7. 关键风险

| 风险 | 对策 |
| --- | --- |
| Agent接入改造不确定 | 优先支持BFF/Sidecar轻量适配，保证Token和Task上下文可透传 |
| 策略验证性能影响工具调用 | 使用策略缓存，优先缓存用户-Agent-工具维度结果 |
| 高危确认链路影响体验 | 先实现单次确认闭环，再扩展批量确认和免确认策略 |
| A2A权限放大 | 委托链必须由策略中心解析，权限和数据范围按交集计算 |
| 联调边界不清 | 每个验收场景指定主责服务和首个失败定位点 |
