# 核心模块能力与接口定义

## 1. 总体口径



核心分工：

- IDaaS：负责用户登录与用户身份认证。
- IAM：负责 Agent 身份认证与 Agent 权限身份管理。
- Agent Gateway：负责 Token、凭证上下文、Cookie
- 策略中心：负责委托授权、工具策略权限判断
- MCP Gateway：负责 MCP 工具调用入口、鉴权执行


关键边界：

- Agent 只能拿任务级 Token，不能拿用户 Cookie。
- MCP Gateway 调传统业务 API 是直连，不经过 Agent Gateway。
- Agent Gateway 只在 Token 验证和 Cookie 换取时被 MCP Gateway 调用。
- 策略中心只返回权限结果不执行工具调用。

## 3. 各模块能力与核心接口

### 3.1 IDaaS：用户登录与用户身份认证

核心能力：

- 用户 SSO 登录。
- 校验用户 Cookie / IDaaS 登录态是否有效。
- 返回用户身份上下文，如 userId、tenantId、appName、组织信息。
- 支持用户 IDaaS 登录态刷新和失效判断。

核心接口：

| 接口 | 调用方 | 说明 |
|---|---|---|
| `POST /idaas/session/validate` | Agent Gateway | 校验用户 Cookie / IDaaS 登录态 |
| `GET /idaas/users/{userId}/context` | Agent Gateway | 获取用户身份和环境上下文 |
| `POST /idaas/session/refresh` | Web Copilot / Agent Gateway | 刷新用户 IDaaS 登录态 |


验收点：

- 用户登录必须经过 IDaaS。
- Cookie / IDaaS 登录态失效时，Agent Gateway 不能生成任务级 Token。
- IDaaS 能返回 userId、tenantId、appName 等上下文。

### 3.2 IAM：Agent 身份认证

核心能力：

- 获取 Agent 身份令牌
- 校验 Agent 是否为合法注册主体。


核心接口：

| 接口                              | 调用方           | 说明 |
|---------------------------------|---------------|---|
| `GET /iam/agents/agent-token`   | Agent         | 获取 Agent 身份令牌 |
| `POST /iam/agents/authenticate` | Agent Gateway | 认证 Agent 身份 |


验收点：

- Agent 身份认证必须经过 IAM。
- Agent 未认证或状态不可用时，Agent Gateway 不能生成任务级 Token。

### 3.3 Agent Gateway：Token、凭证上下文、Cookie 网关

核心能力：

- 接收 Web Copilot 的任务级 Token 生成请求。
- 调用 IDaaS 校验用户身份。
- 调用 IAM 校验 Agent 身份。
- 生成任务级 Token，绑定 userId、agentId、taskId、appName。
- 内部管理凭证上下文，并加密保存用户 Cookie；该内部 ID 不对 Agent 暴露。
- 提供 Token 验证能力给 MCP Gateway。
- 提供 Cookie 换取能力给 MCP Gateway。


核心接口：

| 接口 | 调用方 | 说明 |
|---|---|---|
| `POST /api/v1/tokens/generate` | Web Copilot | 生成任务级 Token |
| `POST /api/v1/tokens/verify` | MCP Gateway | 验证 Token 是否有效 |
| `POST /api/v1/cookies/exchange` | MCP Gateway | 使用 Token 换取用户 Cookie |
| `POST /api/v1/tasks/{taskId}/close` | Web Copilot | 结束任务并失效 Token |


验收点：

- 用户身份来自 IDaaS。
- Agent 身份来自 IAM。
- Agent 只能拿到任务级 Token，不能拿到用户 Cookie。
- Token 失效后，MCP Gateway 验证必须失败。
- MCP Gateway 可以通过有效 Token 换取 Cookie。

### 3.4 策略中心：委托授权与权限判断

核心能力：

- 管理用户对 Agent 的委托授权。
- 管理工具标签、风险等级和数据范围。
- 判断 Agent 是否可以调用某个 MCP 工具。
- 返回权限结果 allowed=true/false。
- 返回数据范围，如 appName、tenantId、datasourceIds。
- 支持高危工具返回需要用户确认。


核心接口：

| 接口 | 调用方 | 说明 |
|---|---|---|
| `POST /api/v1/delegations/verify-permission` | MCP Gateway | 校验工具调用权限 |
| `POST /api/v1/delegations` | Web Copilot / 权限中心页面 | 创建委托授权 |
| `GET /api/v1/delegations` | Web Copilot / MCP Gateway | 查询委托授权 |


验收点：

- 已授权时返回 allowed=true。
- 未授权时返回 allowed=false。
- 高危工具能返回需要确认。
- 无权限时不允许 MCP Gateway 继续调用传统业务 API。

### 3.5 MCP Gateway：工具调用与鉴权执行

核心能力：

- 向 Agent 暴露 MCP 工具列表。
- 接收 Agent 的工具调用请求。
- 调用 Agent Gateway 验证 Token。
- 调用策略中心判断工具权限。
- 调用 Agent Gateway 换取 Cookie。


验收点：

- MCP Gateway 必须先验证 Token。
- MCP Gateway 必须调用策略中心判断权限。
- 有权限时才能调用传统业务 API。
- 调传统业务 API 时必须注入 dataRange。
- 调传统业务 API 不经过 Agent Gateway。
- 无权限时必须返回授权提示。

## 7. 核心验收标准

- 用户登录必须走 IDaaS。
- Agent 身份认证必须走 IAM。
- Agent 不能拿到用户 Cookie，只能拿任务级 Token。
- Agent Gateway 不做工具鉴权。
- 策略中心必须能返回 allowed 和 dataRange。
- MCP Gateway 有权限时才能调用传统业务 API。
- MCP Gateway 调传统业务 API 不经过 Agent Gateway。
- Token 失效后，MCP 工具调用必须失败。
- 无授权时，MCP Gateway 必须返回授权提示，不允许继续调用业务 API。
